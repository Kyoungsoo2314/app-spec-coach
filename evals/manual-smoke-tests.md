# 수동 스모크 테스트

아래 테스트는 Skill을 Codex에 설치한 뒤 새 대화에서 수행한다. 아직 실행하지 않았다면 결과는 `NOT RUN`이다.

## S01 — 신규 앱 요청

입력:

```text
재고관리 앱 만들어줘.
```

기대:

- 바로 코드 작성 대신 명세 정리를 제안한다.
- 선택 경로를 제공한다.
- 사용자가 동의하기 전까지 구현을 시작하지 않는다.

## S02 — 쉬운 인터뷰

사용자:

```text
같이 정리하자.
```

기대:

- 한 문장 재정의를 먼저 한다.
- 현재 모호함을 `약 N%`로 표시한다.
- 첫 질문은 기술 선택이 아닌 실제 업무 상황의 선택형 질문이다.

## S03 — 반복 질문 방지

사용자:

```text
기록은 지금 Excel에 있어.
```

기대:

- 저장 위치를 확인된 결정으로 기억한다.
- 같은 질문을 다시 하지 않는다.
- 다음 업무 영향이 큰 결정으로 이동한다.

## S04 — 이미지 선택 경로

업무 흐름과 주요 화면을 정리한 뒤:

```text
목록 화면을 이미지로 한번 보고 싶어.
```

기대:

- 사용자 동의와 시각 검토의 목적을 확인한다.
- 현재 환경의 이미지 capability를 선택적으로 사용한다.
- 이미지에만 있는 기능을 SPEC에 자동 추가하지 않는다.

## S05 — 이미지 불가 경로

이미지 capability를 사용할 수 없거나 실패하는 환경에서 같은 요청을 수행한다.

기대:

- 텍스트 화면 구조와 SPEC 작성을 계속한다.
- 이미지 실패를 전체 작업 실패로 보고하지 않는다.

## S06 — SPEC LOCK과 승인

핵심 결정이 끝난 뒤:

기대:

- SPEC LOCK 조건을 요약한다.
- 구현 계약을 만든다.
- “이 SPEC으로 구현까지 진행할까요?”라고 별도로 묻는다.

## S07 — 검증 상태

브라우저·외부 서비스가 없는 상태에서 완료 보고를 요청한다.

기대:

- 실행하지 않은 항목은 `NOT RUN` 또는 `BLOCKED`다.
- 실제 실행한 항목만 `PASS`다.

## S08 — 최종 시안 동의 게이트

초보자가 앱을 만들고 있고 핵심 흐름은 정리됐지만 메뉴·화면·대시보드·필수 정보가 아직 논의 중인 상태에서 진행한다.

기대:

- 이미지 시각 검토 기능은 먼저 안내하지만, 메뉴·화면·대시보드·필수 정보가 정리되기 전에는 이미지를 생성하지 않는다.
- 논의가 끝난 뒤 `① 최종 시안 보기 / ② 이미지 없이 텍스트 SPEC으로 계속`을 제안한다.
- 사용자가 `①`을 선택하면 같은 턴에 실제 이미지 도구 호출과 결과가 나온다.
- 이미지 피드백을 받은 뒤 최종 SPEC 질문과 LOCK을 진행한다.
- 이미지에만 있는 기능을 요구사항으로 자동 추가하지 않는다.
- 사용자가 거부하면 `SKIPPED`, 이미지 capability가 없거나 실패하면 `NOT RUN` 사유를 남기고 텍스트 흐름을 계속한다.

## S09 — 종료 상태와 후속 질문

기획 내용은 거의 정리됐지만 SPEC 확정과 앱 구현이 아직 남은 상태에서 진행한다.

기대:

- `현재 단계:`가 표시된다.
- SPEC 1.0 확정 전이면 확정 여부를 묻거나, SPEC LOCK 후면 구현 승인 여부를 묻는다.
- `다음 행동:`과 사용자의 선택지가 표시된다.
- “기획은 끝났지만 앱 구현은 아직”처럼 현재 상태를 구분한다.
- 요약만 남기고 후속 질문 없이 종료하지 않는다.
