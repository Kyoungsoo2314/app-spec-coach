# 문제 해결

## Skill이 보이지 않음

1. 저장소 경로와 Skill 폴더 구조를 확인한다.
2. `python .agents/skills/app-spec-coach/scripts/doctor.py .`를 실행한다.
3. Codex에서 새 대화를 시작하거나 재시작한다.
4. 현재 환경이 저장소 범위 Skill 또는 사용자 범위 Skill을 읽는지 확인한다.

## 바로 코딩을 시작함

다음 항목을 확인한다.

- Skill이 실제로 설치·발견되었는가
- 요청이 단순 수정이 아니라 신규 앱 요청이었는가
- 사용자가 이미 충분한 SPEC을 제공했는가
- 사용자가 명시적으로 즉시 구현과 가정 기반 초안을 선택했는가

`앱 기획해 보자`로도 같은 문제가 재현되면, 사용자-facing trigger 문구와 설치본 `SKILL.md`의 `1.1 호출 문구` 절을 확인한다. 이 문구는 `앱 만들어줘`와 같은 신규 앱 코칭 흐름으로 연결되어야 한다.

가정 기반 초안이었다면 가정과 최소 완료 기준을 먼저 공개했는지 확인한다.

## 질문을 너무 많이 함

한 번에 1~3개로 줄이고 새 주제의 첫 질문은 하나로 만든다. 이미 답한 내용은 STATE에 기록하고 다시 묻지 않는다. 기술 질문은 실제 업무 상황으로 바꾼다.

## 이미지 생성이 안 됨

이미지는 선택 기능이다. 텍스트 화면 구조, SPEC, 구현 계약으로 계속 진행한다. 이미지에만 있는 기능은 요구사항으로 취급하지 않는다.

## SPEC이 너무 빨리 LOCK됨

LOCK 체크리스트에서 사용자·흐름·입력·결과·예외·비목표·성공 기준을 다시 확인한다. 숫자가 약 15% 이하라는 이유만으로 핵심 판단이 비어 있는 상태를 LOCK하지 않는다.

## 구현 후 검증이 불분명함

각 완료 기준에 실제 명령·화면·데이터 증거를 연결한다. 실행하지 않았다면 `NOT RUN`, 외부 조건 때문에 못 했다면 `BLOCKED`다. 둘 다 `PASS`가 아니다.

## 다른 하네스와 충돌함

기존 `AGENTS.md`, 테스트, 실행 하네스, Skill을 삭제하지 않는다. 앱 기획 스킬은 확정 SPEC·구현 계약·검증 기준만 전달하고 실행 책임은 기존 체계에 맡긴다.
