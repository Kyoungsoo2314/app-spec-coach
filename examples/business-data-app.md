# 예제: 소규모 매장 재고 관리

이 예제는 여러 직원이 실제 업무 기록을 함께 쓰는 데이터 앱이다. 화면 목업만으로 완료하지 않고 실제 저장과 재조회를 요구한다.

## 한 문장

이 앱은 매장 직원이 입고·사용·보충 요청을 기록하고 현재 부족한 상품을 빠르게 판단하도록 돕는다.

## 핵심 흐름

```text
상품이 들어옴
→ 입고 수량과 날짜 기록
→ 현재 재고 목록 재조회
→ 부족 상태 확인
→ 보충 요청 생성
→ 요청 상태를 처리 완료로 변경
```

## MVP

- 상품 목록과 현재 수량
- 입고 기록
- 사용·차감 기록
- 부족 기준
- 보충 요청과 상태
- 검색·필터
- 직원이 실제로 저장한 뒤 새로고침해도 유지

## 비목표

- 공급업체 자동 주문
- 판매 결제
- 예측 수요 분석
- 근거 없는 대시보드 통계

## 확인할 질문

- 여러 직원이 동시에 같은 상품을 수정하는가?
- 수량이 맞지 않을 때 누가 조정하고 이력을 남기는가?
- 상품명 중복을 어떻게 막는가?
- 기록을 얼마나 오래 보관하는가?
- 어느 네트워크와 기기에서 쓰는가?

## 성공 기준

직원이 입고를 기록한 뒤 다른 직원이 목록을 새로 열어도 같은 수량을 확인할 수 있고, 부족 상품을 찾아 보충 요청 상태까지 바꿀 수 있다.
