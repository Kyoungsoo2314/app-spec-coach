# 모호함 루브릭

모호함은 정밀한 과학적 측정값이 아니라 인터뷰 진행 방향을 보여주는 약식 지표다. 사용자에게는 항상 `약`을 붙여 표시한다.

## 확인도

각 항목의 확인도는 다음 중 하나다.

- `0`: 확인되지 않음
- `0.5`: 일부 확인됨
- `1`: 충분히 확인됨

해당 앱에 필요 없다는 사실이 확인된 항목은 `1`로 처리한다. 필요 여부 자체가 미확정이면 `0`이다.

## 가중치

| 항목 | 가중치 | 확인 질문 예시 |
|---|---:|---|
| 해결 문제 | 10 | 무엇이 반복적으로 불편한가? |
| 주요 사용자·사용 시점 | 8 | 누가 언제 쓰는가? |
| 현재 업무·불편 | 8 | 지금은 어떤 순서로 처리하는가? |
| 입력·기록 데이터 | 8 | 무엇을 입력·기록하는가? |
| 결과·판단 정보 | 8 | 입력 뒤 무엇을 확인하거나 결정하는가? |
| 핵심 업무 흐름 | 12 | 시작부터 끝까지 어떤 단계인가? |
| MVP·비목표 | 8 | 오늘 꼭 필요한 것과 나중 것은 무엇인가? |
| 메뉴·화면·이동 | 8 | 어떤 업무 단위로 찾아야 하는가? |
| 상태·예외 | 7 | 누락·중복·취소·실패 때 어떻게 하는가? |
| 성공 기준 | 8 | 무엇이 되면 실제로 도움이 된 것인가? |
| 데이터 보존 | 5 | 사라지면 안 되는 기간과 복구 필요는? |
| 인증·보안 | 4 | 누가 무엇을 볼 수 있고 할 수 있는가? |
| 계산·업무 규칙 | 3 | 자동 계산 또는 판정이 필요한가? |
| 운영 환경 | 3 | 어느 기기·네트워크·장소에서 쓰는가? |
| **합계** | **100** | |

## 계산

```text
모호함 % = Σ(가중치 × (1 - 확인도))
```

표시값은 약 5% 단위로 반올림할 수 있다. 내부적으로 더 세밀한 값을 사용하더라도 사용자에게 정밀도에 대한 과도한 인상을 주지 않는다.

## 전환 기준

| 약식 모호함 | 가능한 행동 |
|---:|---|
| 70% 이상 | 아이디어 재정의와 핵심 사용자·문제 질문 |
| 40% 이하 | 업무 흐름과 최소 메뉴·화면 제안 |
| 30% 이하 | SPEC 초안과 선택적 시각 검토 |
| 15% 이하 | 마지막 핵심 확인과 SPEC LOCK 검토 |

전환 기준은 자동 행동 명령이 아니다. 숫자가 낮아도 핵심 사용자 판단이 비어 있으면 LOCK하지 않는다.
