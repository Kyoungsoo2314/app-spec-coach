# 위험도별 인터뷰 깊이

앱의 크기보다 실제 영향과 데이터 위험을 기준으로 질문 깊이를 조절한다.

## 작은 개인용 도구

예: 개인용 계산기, 한 사람이 쓰는 간단한 기록 도구.

확인할 것:

- 해결할 문제
- 사용자와 사용 시점
- 핵심 흐름
- 입력과 출력
- 필요한 화면
- 예외
- 오늘 버전과 비목표
- 성공 기준

근거 없이 로그인, 서버, 복잡한 권한, 다중 사용자 DB를 추가하지 않는다.

## 실제 업무용 데이터 앱

다음 항목을 추가한다.

- 데이터 항목과 필수 여부
- 검색·필터·정렬
- 상태값과 상태 전환
- 중복·수정·삭제 규칙
- 저장·재조회·백업
- 여러 사용자의 동시 작업
- 오류가 났을 때 복구 방법
- 테스트 데이터와 실제 데이터 분리

하드코딩 샘플, 새로고침하면 사라지는 가짜 CRUD, 화면만 바뀌는 버튼은 실제 업무 앱의 완료로 인정하지 않는다.

## 민감·고영향 앱

다음 신호가 있으면 질문 깊이를 높인다.

- 개인정보·의료정보
- 결제·중요한 금액
- 직원·고객·환자 등 여러 사람의 기록
- 외부 인터넷·LAN 접근
- 파일·사진 업로드
- 실제 운영에 바로 사용하는 기록

검토할 것:

- 최소 수집
- 사용자별 접근 범위와 행동 권한
- 민감정보를 로그·예제·스크린샷에 남기지 않는 방법
- 보관 기간과 삭제·복구
- 백업·복구 절차
- 테스트 데이터 분리
- 배포 네트워크 범위
- 실제 운영 전 별도 보안·법률 검토 필요성

법률·규정 준수를 자동으로 보장한다고 말하지 않는다. 필요한 경우 “전문가 검토 필요”를 SPEC의 외부 확인 항목으로 남긴다.
