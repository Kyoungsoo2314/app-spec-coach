# 공존 정책

앱 명세 코치는 다른 하네스나 프로젝트 규칙을 대체하지 않는다.

## 우선순위

1. 사용자 요청과 명시적 승인
2. 현재 프로젝트의 `AGENTS.md`와 기존 운영 규칙
3. LOCK된 프로젝트 SPEC
4. 앱 명세 코치의 일반 정책
5. 추정

상위 규칙과 충돌하면 충돌을 설명하고, 사용자 또는 프로젝트 규칙을 따른다.

## 보존

다음 항목을 삭제·덮어쓰기·비활성화하지 않는다.

- 기존 `AGENTS.md`
- 다른 Skill과 Plugin
- 기존 테스트·빌드·배포 설정
- 기존 SPEC과 상태 문서
- 사용자가 만든 코드와 문서

새 상태 문서가 필요하면 먼저 기존 문서 위치와 형식을 확인한다.

## 실행 하네스와 연결

별도 계획·실행 하네스가 있다면 앱 명세 코치는 다음 산출물만 전달한다.

- 확정 SPEC
- 비목표
- 구현 계약
- 검증 기준
- 남은 외부 확인 사항

실행 하네스의 명령·파일·상태를 임의로 바꾸지 않는다.

## 저장 위치

실제 앱 프로젝트 안에서는 가능하면 다음을 사용한다.

```text
.app-spec-coach/
├── STATE.md
├── SPEC.md
├── IMPLEMENTATION_CONTRACT.md
└── VERIFICATION.md
```

프로젝트에 이미 명세 체계가 있으면 새 폴더를 만들지 않고 기존 체계에 맞춘다.
