# 구현 계약 정책

구현 계약은 “코드가 있다”가 아니라 “사용자가 정한 결과를 실제로 확인할 수 있다”를 정의한다.

## 구성

- 필수 산출물
- 사용자 수용 기준
- 데이터 흐름 기준
- 화면·이동 기준
- 오류·예외 기준
- 비목표
- 실제 검증 명령과 증거 위치

## 수용 기준 작성

좋은 기준:

```text
사용자가 상품을 등록하고 저장한 뒤 새로고침해도 같은 상품을 목록에서 다시 찾을 수 있다.
```

나쁜 기준:

```text
상품 기능이 완성되어 있다.
```

각 기준은 가능하면 다음을 포함한다.

- 누가
- 어떤 행동을 하고
- 어떤 실제 결과를 확인하는가
- 어떤 예외가 발생하면 어떻게 되는가

## 최소 데이터 계약

업무 데이터 앱은 다음 흐름을 실제로 확인한다.

```text
입력
→ 실제 저장
→ 새로고침 또는 재실행
→ 재조회
→ 수정
→ 결과 확인
```

하드코딩 샘플, 화면 상태만 바뀌는 가짜 저장, 재실행 시 사라지는 기록은 해당 기준을 만족하지 않는다.

## 범위 보호

구현 중 발견한 기능은 세 가지로 분류한다.

| 분류 | 조치 |
|---|---|
| SPEC에 있음 | 구현하고 검증 |
| SPEC과 충돌 | 사용자 확인 전 보류 |
| 유용하지만 없음 | 확장 후보에 기록 |

## 구현 전 승인

계약을 만들었다고 자동 구현하지 않는다. 사용자에게 SPEC과 구현 계약을 확인할 기회를 제공한다.
